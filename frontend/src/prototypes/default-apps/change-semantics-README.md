# Default Apps 修改交互原型

打开 [change-semantics-prototype.html](change-semantics-prototype.html) 即可运行。单个 HTML 文件，CSS、数据和 JavaScript 全部内联；可在 Finder 中双击，不需要开发服务器。所有操作仅改变内存示例，不连接 Wails 或 macOS，也不会修改真实默认应用。刷新或「重置示例」恢复起点。

本原型回答[修改默认关联时，用户如何确认结果与处理失败？](../../../../.scratch/default-apps-v1/issues/05-change-semantics-prototype.md)，沿用用户选择的 A「应用优先」布局。用户于 2026-11-05 已选定逐项立即修改、手动改回和持续等待；具体决议以该工单 Answer 为准。暂存、批量、恢复和停止等待等比较操作保留在原型中，不是首版产品功能。

## 体验方式

顶部可比较「逐项立即修改」与「暂存后应用」。切换方式会重置演示；切换左侧应用或「应用／文件类型／URL 协议」浏览入口会保留共享的请求和草稿。

- **逐项立即修改**：点击行内「设为此应用」立即提交该项。用「送达系统结果」模拟完成回调，再用「重新回读」查询实际默认。提交和回调成功均不会提前把行内默认改成目标。
- **暂存后应用**：点击行内按钮仅记录草稿；「应用 N 项」依次提交，每项都需系统结果和回读。失败后继续下一项，已成功项保留；「丢弃选择」清除尚未提交的草稿。HTTP 与 HTTPS 是独立关联项。
- **自由操作**：点击关联项名称定位详情，选择模拟系统结果，体验停止等待、晚到回调、恢复或退出。停止等待只结束界面等待，结果仍待决；恢复是一项新请求。
- **情景演练**：点击情景页签会重置到已知起点，再依次点击深色按钮。故意尝试不可执行操作的步骤会给出原因，并保留既有请求。

页面显示所查看关联项的修改前副本、目标路径、界面等待、系统返回、实际回读和查询状态。「完整状态与事件记录」保留全部关联项、请求历史及模拟系统状态，便于检查每次操作；它是原型诊断区，不是产品用户流程。

## 九个情景

| 情景 | 观察重点 |
| --- | --- |
| 单项成功 | 提交、系统结果、回读分别发生；回读后确认目标路径 |
| 系统拒绝 | 模拟错误与实际默认分开显示；检查后再次提交是新请求 |
| 停止等待后成功 | 停止等待不撤回请求，禁止重复提交，接受晚到结果 |
| 另一安装副本 | 回调成功，但同一 bundle ID 的不同路径仍显示差异 |
| 批量部分成功 | PDF、HTTPS 成功，HTTP 模拟失败；没有原子事务或自动回滚 |
| 回读仍是旧值 | 返回成功后仍可能显示旧默认；再次查询不凭时间变成成功 |
| 恢复是一项新修改 | 恢复也需确认与回读，且可能失败 |
| 原应用已卸载 | 无法恢复指定副本，不自动选择另一份同名安装 |
| 待决时退出 | 退出时提示，重新打开查询当前默认，旧回调仍未知 |

## 模型与证据边界

第一个 script 中的 `ChangeModel` 是纯 reducer：只接收状态和动作并返回新状态，不访问 DOM、网络、存储、计时器或原生接口。第二个 script 是页面与演练的薄壳。没有新增框架、依赖、产品集成或原型测试。

[原生探针结论](../../../../.scratch/default-apps-v1/issues/08-native-behavior-probe.md)提供两项相关实机观察：取消 Go/Wails 等待后，用户随后允许，晚到回调仍成功；选择一份应用后，系统回读可落到具有相同 bundle ID 的另一安装副本。原型使用常见应用展示相同的状态关系；**PDF、JPEG、HTTP、HTTPS 的这些演示结果不是在这台 Mac 上实测所得**。

系统确认拒绝的 NSError 与真实待决请求退出后的最终行为尚未观察。原型中的 `DemoAssociationErrorDomain`、code `1` 完全虚构，仅为展示错误域、代码与描述；正式实现应保留实际原生错误，不据此硬编码取消分类。退出后的模拟完成也不是实机结论。

本原型采用「一次只有一项原生请求；结果未定时暂停新的写入」并允许继续浏览与查询；用户已在持续等待方案中选择这一交互。历史批量方案中的逐项队列和失败后继续，仅用于比较，不属于首版调度需求。退出提示按工单决议采用；恢复入口和停止等待入口保留作历史方案。

模拟重新打开仍使用本页内存保留的目标与旧请求，仅帮助看清「当前默认」和「旧请求结果」的差别；真实产品跨启动保存哪些操作信息留给架构决策。没有持久化，没有自动重放写入。原型知道模拟系统有没有完成，不代表产品能跨进程获知该状态。

恢复针对最近一次请求提交前记录的**具体应用副本**，不代表任意历史回滚或系统原子撤销。这里的应用、版本、路径、支持声明和初始默认均为固定样例，需要在产品实现中替换为实际目录和查询。

## 验证记录

2026-11-05：使用命名浏览器会话 `default-apps-change-semantics` 直接打开 `file://` 本地文件，完成全部九个演练；单项成功经过实际点击核对提交和回调后仍显示旧默认，回读后才确认目标。其余演练通过浏览器中的真实 DOM 按钮驱动，检查每一步和最终状态；没有建立自动测试套件。

批量最终结果为 PDF、HTTPS 的目标路径已确认，HTTP 模拟失败且保留 Safari；副本与旧值情景均显示回读差异。检查恢复请求失败、原副本卸载后阻止恢复、停止等待后阻止重复提交及晚到成功。退出情景重新查询后使用「当前为目标 · 旧请求未知」，不会计入已确认成功请求；还检查了重新打开之后旧模拟请求才完成的顺序。
