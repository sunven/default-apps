# 应用页批量设置

2026-11-14。用户已确认：在应用页勾选多个文件类型，统一设为当前应用；每个应用独立保留勾选，预览固定目标。此文增补[批量设置规格](batch-file-associations.md)，不改变已有执行及最近批次恢复规则。

## 使用流程

1. 选择应用副本，在关联表中勾选文件类型。协议行没有复选框，未解析类型不可勾选；名称、详情和单项设置仍独立操作。
2. 搜索和筛选保留已选项，全选只处理当前结果中的可解析文件类型，包括未滚动到的行。取消全选不影响其他筛选下的已选项。已是该应用的类型仍可勾选，由预览说明无需修改。
3. 操作条显示已选数量和目标应用，支持查看、移除、清空。点击“设为［应用名］…”直接检查并准备预览，不再进入应用选择器。
4. 准备期间可以返回调整；失败时显示原因并可重新准备。预览展示当前默认、目标副本和每项处理方式，明确影响这些类型的所有同类文件。应用来源预览没有“更换应用”；需返回应用页选择其他应用及其清单。
5. 点击“开始设置”才提交；全部无需修改或不可执行时不能开始。受理后沿用现有进度、部分成功、等待、停止后续设置和最近批次结果。

## 勾选归属与生命周期

- 应用副本按规范路径区分，同名、同 bundle ID 的副本不共享勾选。
- 每个应用、文件类型页和拖入文件清单独立；切换应用或入口不会合并或清空。所有未提交勾选仅保存在当前窗口会话中，前端重载或退出后不恢复。
- “查看已选”及其操作捕获来源应用；搜索隐藏的类型仍可检查、移除和提交。准备预览捕获当次清单、顺序及目标路径，之后不随目录刷新改变。
- 返回、关闭、准备失败或未受理均保留勾选。迟到的旧响应不能重开预览、覆盖新错误或结束新操作的忙碌状态。
- 只有受理结果或可信快照确认原提交身份后，才从来源集合移除本次清单中的项目；其他应用和入口不受影响。之后到达的旧应答不能再次清理新勾选。
- 目标副本消失时沿用查询与提交检查，显示不可用，不自动选择同名副本；原集合保留。已选类型变得不可解析时，由预览列为不执行。

## 与现有批量流程衔接

`BatchWorkflow` 持有按应用路径划分的只读勾选集合；选择动作接收明确的来源路径。新增应用来源、固定目标及准备状态，界面只调用动作并展示状态，不另设执行队列。

复用 `PrepareBatch`、`StartBatch`、`ReconcileBatchStart`、停止和继续接口。Go 服务、Wails 绑定及配置格式没有变更，无需迁移。开始丢应答只核对原预览身份，重载也不重发。

固定目标仅约束从应用页创建的新预览。开始后的批次使用现有最近批次规则；继续或重新处理问题项时仍可按原规则明确选择其他副本，形成相应的新批次。

未增加默认状态筛选、收藏、历史或自定义快捷键。
