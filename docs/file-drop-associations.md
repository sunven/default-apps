# 拖入文件设置默认应用

状态：2026-11-11，Q1–Q10 及完整方案均已由用户确认；实现、自动测试、真实 Finder 拖入与预览验证、普通应用打包已完成。验证范围见[验收记录](file-drop-associations-validation.md)。本文是文件拖入功能的增补规格。

用户目标：将文件拖到 Default Apps，快速选择其所属文件类型的默认应用。

## 已确认决策

| 问题 | 用户确认的行为 |
| --- | --- |
| Q1 修改范围 | 拖入文件用于定位文件类型，设置作用于整个类型；提交前明确影响所有同类文件。 |
| Q2 拖入位置 | 首版接收拖到已打开应用窗口的文件，并提供明确拖放提示；Dock 图标接收与未启动时接收不在本次范围。 |
| Q3 多文件 | 支持一次拖入多个文件，按实际文件类型去重；多个类型统一选择一个目标应用，复用已有批量设置流程。 |
| Q4 输入边界 | 只接收普通文件；文件夹、应用包、文字和链接不支持，不递归扫描文件夹。混合拖入时保留可识别文件，列出其余项目及原因。 |
| Q5 主流程 | 展示文件类型、对应文件和当前默认的识别清单；允许移除类型，再统一选择应用，预览后明确开始设置。单一类型使用同一流程；拖入及选择应用均不直接修改系统设置。 |
| Q6 临时使用与保存 | 拖入结果仅供本次设置使用，不自动保存文件路径或新增手动关联；提供“保存为手动关联”选项。取消后丢弃本次临时清单。 |
| Q7 无法识别与歧义 | 无法识别的文件列明原因；出现多个可能类型时要求明确选择一个，未确定项目不参与设置，其他有效项可以继续。不仅凭扩展名猜测类型。 |
| Q8 连续拖入与弹窗 | 识别清单打开时，新文件追加并按类型去重，保留已有选择。正在识别、选择应用、预览或打开其他弹窗时暂不接收，并提示原因；返回识别清单后可继续追加，不改变已展示的预览。 |
| Q9 执行期间 | 已有批次正在执行或有结果未定的修改时，暂不接收文件，并提示先处理当前设置；不排队、不自动重试。执行沿用现有批量设置的失败、等待、停止及恢复规则。 |
| Q10 其他选择及明确保存 | 拖入清单独立于文件类型页已有勾选，不自动合并或清空。主动保存的手动关联在取消本次设置后继续保留；保存失败提示，并允许继续设置。只有“开始设置”提交本次清单；旧批次有未执行项时先沿用现有规则明确处理旧批次。 |

“文件直达”见[领域词汇表](../GLOSSARY.md)。它不表示只给某一份文件设置例外，也不表示仅打开一次。

## 已核对事实

- 当前“补充文件类型…”中的原生文件选择用于识别整个类型，随后需保存手动关联。
- 现有详情已提供当前默认、系统候选及手动选择应用；修改对象是文件类型，应用副本按路径区分。
- 已有多文件类型统一使用一个应用的批量设置能力及其执行、等待、恢复规则。
- 正式应用尚无拖放接收入口；现有识别服务会主动打开文件选择器，需要补充接收拖入文件的路径。
- 类型识别使用文件 URL 的内容类型；设置使用系统面向内容类型的默认应用接口。
- [早期功能建议](feature-expansion-ideas.md)曾提出文件直达，但其中建议不自动成为本次已确认需求。

依据：[手动识别界面](../frontend/src/ManualActions.tsx)、[手动关联服务](../internal/manual/service.go)、[原生识别与查询](../internal/native/native_darwin.m)、[原生修改](../internal/native/dispatcher_darwin.m)、[批量设置规格](batch-file-associations.md)。

## 完整流程

1. 用户将一个或多个普通文件拖到已打开的窗口；窗口呈现明确拖放提示。拖入其他内容时说明不支持，混合输入中的有效文件仍进入识别。
2. 文件只用于识别所属类型，按实际文件类型身份合并，保留对应文件的展示信息；同扩展名的不同实际类型不混为一类。无法识别及不支持的输入各自说明原因。有多个可能类型时由用户明确选择；未明确的项目不参与设置。
3. 展示识别清单、对应文件和各类型当前默认。用户可以移除类型、追加文件，也可以明确保存手动关联；保存不是设置默认应用的前置步骤。没有确定类型时不能进入设置。
4. 为清单中保留的类型统一选择一个具体应用副本。沿用现有批量设置的候选排序、覆盖情况与“选择其他应用…”能力；同名应用副本仍按实际路径区分。
5. 展示现有批次预览：类型、当前默认、目标及不执行原因，并明确说明影响整个文件类型。已是目标的类型跳过，查询失败或无法确定当前默认的类型按现有规则列为不执行。用户可以返回调整或取消；预览期间不接收新拖入。
6. 用户点击“开始设置”才固定清单并进入现有批量执行。只有一个类型时也走同样流程。开始前先处理旧批次剩余项；执行与结果展示复用既有能力，不再建立独立执行队列。
7. 取消时丢弃本次临时清单；已经明确保存的手动关联保留。文件直达本身不持久保存拖入路径，不自动保存手动关联；已经开始的批次按现有规则保存类型、目标与进度。

## 状态与现有能力的衔接

| 状态 | 新拖入的处理 |
| --- | --- |
| 主窗口可用，无其他阻塞状态 | 接收并识别，展示清单 |
| 识别清单打开，当前无识别任务 | 追加文件，按类型去重并保留已有选择 |
| 正在识别 | 暂不接收，说明识别进行中 |
| 选择应用、预览或其他弹窗打开 | 暂不接收，说明应返回清单或关闭当前面板 |
| 批次执行或有结果未定的请求 | 暂不接收，说明先处理当前设置；不排队 |

上述限制叠加适用，不能因为识别清单仍在就绕过执行或待决请求的限制。暂不接收的输入不会在之后自动处理。

现有批量设置规格继续决定修改请求的结果：明确失败继续，外部变化跳过并要求重新确认，结果未定等待；停止只阻止后续未提交项，重开不自动继续或重放。成功仍要求系统完成成功且回读匹配具体目标副本，拖放成功和识别成功均不表示默认应用已修改。

“保存为手动关联”失败只影响该项可选保存，不强制关闭清单。实际开始设置仍需通过现有批次及未定请求的必要持久化检查；若配置故障导致这些检查也失败，沿用现有规则阻止或暂停修改，不能跳过必要保存。

## 验收场景

以下是已确认行为的验收清单，实际覆盖与观察边界见[验收记录](file-drop-associations-validation.md)。

| 场景 | 预期行为 |
| --- | --- |
| 单个 PDF | 显示对应类型、文件和当前默认；选应用后先预览，明确影响同类文件；只有开始设置才提交 |
| 两个 PDF 加一个 Markdown | 根据实际类型识别为两项；同类型文件合并，仍可查看对应文件；一次选择共同应用 |
| 同扩展名、不同实际类型 | 保持类型身份独立，不按扩展名错误合并 |
| 普通文件混合文件夹、应用包、文字或链接 | 保留可识别文件，列明不支持项目；不递归文件夹 |
| 无法识别、类型歧义 | 说明原因或要求明确选择；未确定项不提交，其他有效项可继续 |
| 目录外类型 | 不要求先保存手动关联即可设置；没有自动新增持久手动项 |
| 连续拖入、重复拖入 | 清单阶段追加、去重并保留选择；识别中明确拒收新输入；不出现重复设置项 |
| 应用选择、预览或其他弹窗打开 | 暂不接收，不悄悄改变当前目标或预览 |
| 已有文件类型勾选 | 拖入清单独立，原勾选不自动合并或清空 |
| 取消、主动保存后取消、可选保存失败 | 分别丢弃临时清单、保留明确保存的手动项、提示失败但保留设置流程；必要持久化检查继续生效 |
| 执行或结果未定时拖入 | 提示先处理当前设置，不排队、不自动重试 |
| 旧批次有剩余项 | 开始新批次前按现有规则明确处理，不覆盖未处理进度 |
| 失败、外部变化、等待、停止与重开 | 与现有批量设置规则一致，不创建第二套执行或恢复语义 |

实施验证需覆盖识别与去重、清单状态隔离、拖放门控及已有批量服务衔接，并在真实 macOS 应用窗口验证文件拖入。规则测试与真实桌面观察分别记录，不用浏览器模拟拖放代替正式应用接收验证。

## 实现入口

- [窗口拖放接入](../main.go)：启用 Wails 原生文件拖放，将本窗口接收的文件路径通过类型化事件交给界面。
- [逐文件识别](../internal/manual/files.go)：只接收绝对路径的普通文件，逐项返回识别结果或原因；不打开选择器、不读取内容、不保存配置。
- [识别清单](../frontend/src/FileDrop.tsx)：接收限制、追加、按类型去重、明确选型、移除及恢复、当前默认查询和可选保存；临时数据仅保存在本次窗口状态中。
- [批量设置衔接](../frontend/src/Batch.tsx)：标明流程来源，拖入批次不清空已有勾选，提供返回清单入口；执行仍使用原有服务。
- [识别测试](../internal/manual/files_test.go)与[界面集成测试](../frontend/src/App.file-drop.test.tsx)：覆盖混合输入、路径及类型身份、无持久化、取消与迟到响应、面板及执行门控、预览、提交核对和选择隔离。
