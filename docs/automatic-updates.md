## 代码调查结论

- 参考项目的实际发布仅支持 Apple Silicon；生产主窗口启动后延迟一秒检查。它在下载安装后直接重启，本项目按已确认要求增加重启安装确认。
- Wails 3.1.0 已有检查、下载、校验、解包、暂存和整包替换模块，可复用；本项目仍需自有服务与状态呈现。
- Wails 的周期检查接口实际会自动下载，不能用于本次“仅自动检查”要求；应由本工具调用只读检查接口。
- Wails 的重启接口先启动更新助手再请求退出，不能直接依赖现有退出弹窗拦截。需要先协调业务退出决策、阻止新修改进入，再启动助手；取消时不启动助手。
- Wails 更新暂存在目标应用父目录，需要该目录可写，不提供权限提升；支持 ZIP 或 tar.gz 中的 `.app`，DMG 可用于手动分发但不能直接作为自动更新输入。
- 框架在部分换包失败时尝试恢复旧版，但没有断电事务恢复或新版本启动健康检查，不能宣称崩溃自动回滚。
- 调查时 `sunven/default-apps` 的匿名仓库页面、仓库 REST API 和 latest Release API 均返回 404；常规 Git 读取成功，但禁用凭据后需要认证。当时的 `gh` API 凭据也无法读取仓库 metadata。不能据此取得 `private` 字段，但可以确认发布前必须解决匿名访问条件。

调查依据：参考项目 `src/contexts/UpdateContext.tsx`、`src/lib/updater.ts`、`.github/workflows/release.yml`；当前项目 `main.go`、`internal/change/quit.go`；已锁定 Wails 3.1.0 的 `pkg/updater/` 源码。

## 实现方案

- 复用已锁定的 Wails 更新引擎，禁用框架默认更新窗口及自动下载安装流程，由 Go 产品服务提供检查、下载、状态快照与重启安装入口。React 使用现有通知与对话框呈现。
- 产品服务持有检查与下载状态，去重并发操作；窗口关闭提示不取消正在进行的下载。下载失败允许重试，长度未知时显示不定进度，不能伪造百分比。
- 统一版本来源，并在构建和发布时校验 Go 运行版本、应用 plist 和前端包版本一致。稳定版本只向更高版本更新，不降级、不采用预发布。
- 发布明确命名的 macOS ARM64 更新 ZIP，并限定产物选择规则。客户端严格要求对应校验文件及匹配的摘要；校验失败不进入可安装状态。不引入更新包密钥签名。
- 下载与暂存不退出应用；重启安装先与修改服务共同完成退出决策并封住新修改受理，再调用更新引擎。选择留下时不启动更新助手；启动助手失败时恢复可用状态并显示错误。
- 重启安装只替换当前运行副本，沿用手动项和未定记录，不重放已有系统修改请求。更新专用状态不向严格校验的现有配置文档擅自增加字段。
- 发布脚本负责版本同步与校验，工作流由版本标签触发；先完成检查和全部产物，再使正式 Release 对外可用，避免客户端读到半套产物。

## 验收要求

- 检查：正式启动只查一次；无新版、新版、预发布、相同／更低版本、网络失败分别呈现正确状态；开发版不触发真实更新，手动检查不受提示关闭影响。
- 下载：点击才下载；已知／未知长度、重复点击、下载失败重试、校验文件缺失、摘要不匹配均有验证；下载中不提前修改运行中的应用。
- 安装：只读或不可写位置不启动助手；留在应用不启动助手；无待决修改与有待决修改两条确认路径均验证；助手启动失败不造成假退出或永久阻塞。
- 本机端到端：在隔离的测试副本上，以两个不同版本的构建验证检查、下载、确认、替换和重新打开，并核对新版本与原安装位置；不改写日常文件类型或协议的默认应用。
- 发布：验证标签与版本一致、ZIP 顶层应用结构、ARM64 与应用身份、校验文件和更新说明；发布前置条件不满足时明确失败，不上传或发布半成品。
- 交付：提供可运行 `.app`、相关自动化验证结果及本机升级证据；不把尚未执行的 GitHub 正式发布描述为已通过。
