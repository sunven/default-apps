# Default Apps 首版架构方案（已确认）

状态：用户于 2026-11-05 选择采用本提案中的 cgo 路线与服务边界、当前自用验收范围，以及手动配置和单条未定修改记录；对应[首版采用哪条原生桥接路线与服务边界？](../issues/06-architecture-boundary.md)的决议。本文件保留提案文件名，内容已作为首版架构约束；产品目标仍是形成可开发的规格，尚未实现这些服务。

已确定约束来自[关联目录决议](../issues/03-association-catalog.md)与[修改语义决议](../issues/05-change-semantics-prototype.md)：应用优先，文件类型／协议共享状态，区分应用副本；逐项立即修改，实际回读确认，持续等待；待决时暂停新写入，允许浏览和查询，退出前提示结果未知；不提供批量、恢复或撤回按钮。

## 推荐路线与边界

采用 **React / TypeScript → Wails 生成绑定 → Go 领域服务 → 薄 cgo / Objective-C 适配器 → NSWorkspace / UTType**。只编译一个应用主程序，保留 Wails 默认 cgo 后端。桥接证据见[同版本研究](../research/wails-v3-native-bridge.md)和[实机探针](../issues/08-native-behavior-probe.md)。

| 层 | 拥有的职责 | 向上一层返回 |
| --- | --- | --- |
| React 视图 | 浏览方式、搜索、选中关联项、候选选择、焦点和呈现；用户明确提交一次修改 | 用户动作与显示偏好 |
| Go 目录服务 | 合并常用项、应用声明、手动项；关联身份、输入解析、应用副本去重、目录刷新 | 类型化目录与逐项发现问题 |
| Go 修改协调器 | 一次一项的写入门控、请求身份、提交／系统结果／回读状态、事件版本、重查与退出判断 | 请求快照与独立默认观察 |
| Go 本地配置 | 手动补充项和应用位置，以及单条未定修改记录；缓存可失效 | 配置内容、配置读写错误 |
| Darwin 适配器 | UTType、NSURL、应用声明与图标转换；原生查询、异步 setter、NSError 转换；线程和内存 ownership | Go 可拥有的数据，数值请求 ID 与原生 completion |
| Wails 应用壳 | 服务注册、原生文件／应用选择器、主线程调度、窗口生命周期与退出提示 | 本地选择结果和壳事件 |

Go 的领域规则依赖一个小型系统适配器接口和存储接口，使用替身可驱动成功、错误、晚到结果与回读差异。适配器不直接更新 React 状态、不判断所选副本是否生效；前端不直接调用系统 API、不维护另一份权威写入队列。主入口仍保持现有已选 A 布局，具体窗口与焦点规格交给桌面工单。

Swift helper 要多一份进程协议和构建／生命周期；purego 路线需承担 Objective-C ABI 与 block ownership，而且 Wails 整体 purego GUI 是另一个选择。首版自用且已验证 cgo 路线，没有明确收益支持引入这两条替代路线。此处选择不要求修改 Wails 内部源码或依赖其内部 Cocoa 包。

## 身份与查询模型

文件关联项采用系统可解析的 **UTType identifier**，协议关联项采用规范化后的 **scheme**；两类身份带 kind，避免同名键碰撞。扩展名和 MIME 是搜索标签。输入一个扩展名可能返回多项，未解析输入与解析成功但没有默认分别表达。文件选择只用于识别类型，不读取内容、不更改单个文件的关联。

应用副本以系统确认的**规范应用包路径**区分，保留显示路径、名称、版本和 bundle ID。bundle ID 是元数据和副本关系线索，不能代替所选路径。路径标准化应处理真实文件 URL、符号链接和系统文件身份；不通过对所有路径小写来假设磁盘大小写规则。相同规范包位置合并，不同位置分别保留。当前默认或系统候选出现在扫描范围以外时，仍可作为可用副本返回。

自动扫描三个已定目录及其子目录，进入 `.app` 时读取该应用包信息并停止将包内部当普通目录递归；避免符号链接循环。扫描后台进行，部分目录不可读或某份声明损坏返回局部问题与其余结果，不能把它们变成「系统无默认」。手动位置不可用时保留配置并显示不可用，允许重新选择，不悄悄变成同名副本。

查询结果显式区分以下情况：

| 字段／情况 | 含义 |
| --- | --- |
| 关联已解析 | 有可用于公共接口的类型／协议身份 |
| 默认存在 | 查询返回某个具体副本 |
| 默认为空 | 查询成功，但系统未返回默认 |
| 查询失败 | 未得到新事实，保留上次有效观察与错误 |
| 候选为空 | 候选查询成功但列表为空，与默认是否存在独立 |
| 声明支持 | 应用包的声明，不从当前默认或候选推导 |
| 最后有效观察 | 关联身份、实际默认、候选和查询时间／版本；更新失败时可显示旧值 |

不要把 stale、无默认、未解析、错误都压成一个 `null`。时间只用于解释数据新旧，不代表系统修改的保证时限。NSWorkspace 新 API 不带 Viewer／Editor role；首版不增加独立角色设置承诺。

## 服务表面与请求生命周期

以下方法名表达建议职责，最终 Go 文件拆分可在实现时按此边界命名：

| 绑定操作 | 结果与规则 |
| --- | --- |
| 获取／刷新目录 | 返回目录版本、关联项、应用副本、来源和局部问题；扫描完成以事件通知 |
| 解析手动输入／从所选文件识别 | 返回零／一／多个类型及原因；输入歧义交用户选择，不自动写入 |
| 添加手动项／应用位置 | 验证并更新配置；使用原生选择器的结果，取消选择不产生设置动作 |
| 查询关联项 | 独立返回当前默认、候选、有效时间和查询错误；不表示待决写入已经结束 |
| 发起单项修改 | 输入关联身份、目标副本和客户端请求标识；返回已接收的请求快照，不等待系统确认结束 |
| 获取修改快照 | 查询当前进程的请求状态与观察；用于重载、丢失事件和丢失提交应答后的同步 |
| 重新回读 | 只查询，不重发 setter；更新观察及本次修改确认状态 |
| 请求退出／回应提示 | 统一判断待决状态；确认仍退出后不再接收新写入，交应用壳退出 |

客户端在明确提交时生成一次请求标识，丢失应答后查询或复用该标识，不能自动生成新标识重复写入。Go 在当前进程内对同一标识和相同参数返回已有请求；同标识不同目标返回冲突。新一次由用户明确选择的修改使用新标识。进程结束后不以旧标识自动重放。

受理前确认类型可解析、目标 `.app` 存在以及当前没有未定写入；再次读取当前默认作为提交前观察，不能用目录扫描结果当实时默认。若发现默认与用户查看时不同，返回新观察，请用户检查后明确选择；目标已是当前具体副本时直接返回无需修改的观察。

一次受理经过以下阶段：

1. 协调器登记请求并锁住新写入，记录关联、目标、副本及提交前观察，**先保存未定记录再进入原生提交**。保存失败则不调用 setter，返回未提交与存储错误。
2. 用 Wails 公共 `InvokeAsync` 调度短小的原生发起代码，AppKit 主线程只发起调用，不等待系统完成。已接收与已实际提交可分开，避免排队调度时就显示系统已处理。
3. completion 可以来自任意线程。Objective-C 即时复制错误信息，带数值请求 ID 通知 Go；Go 更新权威状态并安排独立回读，不在原生 callback 内阻塞等待 UI。
4. Go 将系统 completion 与回读作为不同字段。系统成功且回读所选规范路径才确认本次修改；错误、另一副本、旧值和查询失败各有可读状态。
5. 完成回读处理后释放本次写入门控。查询失败先保留待回读与重查入口，不按固定时间解锁并宣布成功。系统已返回错误也仍保留独立查询结果。

绑定 promise 不拥有原生请求：调用取消、页面重载或前端监听解除只影响调用者的等待，已经受理的操作由 Go 协调器继续维护。取消与受理竞争时，以协调器登记结果为准；调用者查同一标识恢复状态。首版 UI 持续显示等待，不提供取消等待动作，但生命周期仍需抵抗窗口重载、传输中断与晚到 callback。

用 `application.RegisterEvent` 注册带类型的修改／目录事件。事件包含关联身份、请求标识和单调版本；前端应用新版本，收到后可同步快照。订阅后查询快照，并按版本处理查询／事件交错，避免“快照后才订阅”漏掉极快完成。Go 保留当前请求及会话内必要的最后结果；事件不是唯一状态存储。

## 原生线程、内存与错误

适配器的 C ABI 只传字符串／长度、字节数据和整数标识，不跨边界保存普通 Go 指针、channel、Go string 或 closure。Objective-C 按明确责任复制输入、拥有 block 和对象，返回数据在 Go 复制后按约定释放；使用 autorelease pool。请求登记项直到原生不再可能使用它时才移除，不能因 promise 取消／等待结束提前删除 callback handle。

主线程调度使用 Wails 公开 API，复用其 run loop；不另建 AppKit 主循环，不在 `ServiceStartup` 中阻塞等主线程回调。首次原生查询等应用壳可调度之后再进行；文件系统扫描可在后台，图标转换与 AppKit 工作按受控线程执行，不把十次后台 setter completion 的观察当永久线程保证。

领域错误分为未解析输入、应用不可用、忙、冲突、原生错误、回读失败、配置存储失败。NSError 的 domain、code、description 保留为字段；没有证据时不硬编码「用户取消」。原生 completion 的错误是请求状态内的一部分；绑定校验／传输错误通过类型化错误序列化返回，不因 promise reject 丢失既有请求和回读。

## 刷新与本地状态

目录与真实默认分开刷新：启动时扫描目录；进入关联项和用户手动刷新时查询实际默认；系统 completion 后回读该项；应用回到前台时重查当前所见关联项。后台扫描不阻塞正在显示的旧目录，明确新旧版本；刷新先合并可用结果，再处理已选副本消失。最终焦点／选中行为由桌面工单确定。

不定时全库轮询，不自动重试系统 setter，不把缓存默认当系统真值。可取消过期目录／搜索查询并忽略旧版本结果，这与取消已经提交的修改不是同一种操作。

本地保存手动关联项和手动 `.app` 路径；目录、图标和默认观察是可重建缓存。配置采用版本化 JSON，放在用户 `~/Library/Application Support/Default Apps/` 中，原子写入，敏感本地路径不外发；不引入数据库、云同步或永久操作历史。读取损坏配置时保留文件并报告问题，不覆盖成空数据后声称恢复成功。

另保留**单条未定修改记录**：请求标识、关联身份、目标、副本、提交前默认、阶段和时间。写入发生在原生提交前；因此崩溃后记录只能说明「可能提交」，不能证明一定调用过。正常完成并得到可呈现回读后清除；回读失败、待决退出或崩溃时保留，用于下次启动查询。清除失败时分别呈现已知的系统／回读结果和存储问题，不能将存储失败改写成系统修改失败；旧磁盘记录下次仍按结果未知处理。

再次启动不恢复 callback、不重放 setter。旧请求标成结果未知，查询当前默认并显示与旧目标的关系；即使一致也不把旧 callback 补成成功。旧记录不是当前进程的活请求，不能无限等待一个不会回来的 callback。用户如要发起新修改，先看到「旧请求可能仍会完成」说明，再明确选择；新的请求仍遵守一次一项规则。旧请求获知与否和新请求结果分别表达；用户确认后，新受理请求的记录可替换这条旧记录，不保留永久历史。查询失败时继续提供重查，未得到有效当前观察之前不提交新修改。

用户已选择保存单条未定记录。只保存手动配置的替代方案未采用；不通过状态原型保留内存推定持久化行为，而以本次用户选择和上述记录协议实现。

## 退出整合与支持范围

`application.Options.ShouldQuit func() bool` 可阻止 macOS 应用退出；`Window.RegisterHook(events.Common.WindowClosing, ...)` 可取消窗口关闭。这些 hook 中只检查 Go 状态，触发一次提示并立即返回；不等待系统 setter，也不等前端应答。用户选择留在应用则保留窗口；仍退出则设置一次性放行状态后调用公开 Quit／Close 路径，防止重复提示。

菜单退出、Cmd-Q 与最后窗口关闭都进入统一判断，避免仅拦前端按钮。退出开始后禁止新写入，保存已存在的未定记录并停止后台查询；原生晚到回调应安全地被接收或忽略，不再触碰已销毁 UI。强制结束无法保证提示或清理，因此需要提交前记录，而不是退出时才首次保存。

Wails 的 `OnShutdown`／`ServiceShutdown` 可承担有界资源清理，`PostShutdown` 可做最终日志；**不能把 `app.Run()` 之后的 Go 代码当 macOS 可靠保存点**。原生 setter 没有撤回协议，退出不保证系统请求停止。

本机只读核对：macOS **27.2 / arm64**，Go **1.27.3**，Node **24.15.0**，npm **11.12.1**，Wails CLI／Go 模块／前端 runtime **3.1.0**，cgo 为 1，SDK 来自 `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`。Taskfile 的 C flags、link flags、deployment target 和两份 plist 当前仍写 12；Go 1.27 的下限是 13，现有值不能构成 macOS 12 支持承诺。

首版**验收范围限定当前 macOS 27.2 / Apple Silicon 自用环境**，部署目标与 Go 工具链下限对齐到 13，明确“13 是构建下限，不是已验证全部 13+ 系统”。不构建 Intel／universal，不为了 macOS 12 降级工具链。扩大兼容范围留待以后另行决定与实机验收。

固定 Go 1.27.3（toolchain 与构建前置检查）、Wails CLI／Go 模块／前端 runtime 3.1.0，前端用现有 package-lock 的锁定版本和 `npm ci`；保留 React 18，不顺带升级框架。macOS cgo 构建链接 AppKit 与 UniformTypeIdentifiers，保持主程序及 dev／普通 app 相同的部署目标。首版仅采用本机运行需要的 ad-hoc 签名；分发、公证、更新和商店继续不在范围。最终产品 metadata／模块名称在实现时与稳定 bundle identity 一致，不保留 `changeme` 与脚手架描述。

## 验证边界与已核对来源

实现时对目录规则和修改协调器运行必要的 Go 测试：身份歧义、副本区分、忙门控、相同请求标识、失去调用等待、晚到 callback、错误和回读不一致、事件／快照版本，以及本地配置的损坏和原子更新。原生适配器用独立专用关联在本机做集成验收；模拟结果不能替代真实系统取消／拒绝及待决退出实验。前端验证真实目录规模下的桌面浏览、焦点和状态同步；具体验收清单由后续工单确定。本轮未编写产品服务或运行成品测试。
