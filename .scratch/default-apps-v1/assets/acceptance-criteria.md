# Default Apps 首版验收清单（已确认）

状态：用户于 2026-11-05 确认所列常用项集合，以及「分层验收与明确限制」门槛。本清单归属[哪些验收情景足以让首版规格进入开发？](../issues/07-spec-acceptance.md)，作为其已确认验收约束。以下是未来产品验收条件，不是已通过的测试报告。

## 完成的含义

**规格完成**：范围、身份、用户操作、结果语义、架构与下表验收条件已定案，现有证据及未观察行为清楚，工程实现不再依赖未答产品问题。该状态不要求在规划阶段实现服务或修改日常默认应用。

**成品完成**：在已接受的 macOS 27.2／Apple Silicon 自用范围内，正式 Wails 应用通过下表确定性验收和必测实机流程；受系统触发条件限制的观察按用户选定门槛处理。规格、浏览器原型、独立探针和成品分别记录证据。

以下规则只指定可观察结果及关键边界，模块拆分、索引实现、列表渲染优化和内部函数命名由实现决定。术语以 [GLOSSARY.md](../../../GLOSSARY.md) 为准；更详细行为引用原决议，不从本表推导新的平台承诺。

## 初始常用项

常用项种子固定为下列输入集合。通过正式解析流程得到可用类型；不凭扩展名字符串建立重复默认值，也不硬编码一个扩展名永远只对应一个类型。

| 类别 | 初始输入／展示方向 |
| --- | --- |
| 文稿 | PDF（pdf）、纯文本（txt、text）、RTF（rtf）、Markdown（md、markdown） |
| 图片 | JPEG（jpg、jpeg）、PNG（png）、GIF（gif）、TIFF（tif、tiff）、HEIC（heic）、SVG（svg） |
| 网页与数据 | HTML（html、htm）、JSON（json） |
| URL 协议 | http、https、mailto、webcal |

这是 12 个常用格式方向与 4 个协议种子，**不等于归一化目录必然只有 16 行**。真实目录还合并应用声明和手动项；相同身份合并来源，不同类型共享扩展名仍展开。某个种子在当前系统未解析时显示原因及文件识别入口，不虚构系统类型。这里不新增 MIME 独立默认、角色设置或全系统完整枚举承诺。

## 验收矩阵

层级：**规则**＝Go 领域服务、存储及可替换适配器的确定性验证；**界面**＝真实前端用户操作与服务同步；**原生**＝正式 Wails `.app` 在本机的集成观察。规则替身负责精确安排故障和竞态，浏览器演示不代替原生结果。

| 编号 | 用户场景／触发 | 必须观察到的结果 | 验证层级 |
| --- | --- | --- | --- |
| CAT-1 | 初次打开，扫描三个常规目录及子目录，包含一份损坏声明和一个不可读位置 | 返回可读的应用与声明，局部问题可见；不递归成内嵌 helper 全目录，不因符号链接循环卡住；目录扫描不改变默认 | 规则＋原生只读 |
| CAT-2 | 同一类型有 jpg/jpeg；一个扩展名又对应两个类型；种子与声明重复 | 按 kind＋已解析类型／协议身份合并来源；多个标签仍是同一默认，歧义类型分行显示 | 规则＋界面 |
| CAT-3 | 手动补充扩展名／协议；未知扩展名后选择真实文件识别；取消选择器 | 可解析后查询，歧义由用户选择；仍不可解析时禁写并解释；取消不添加或写入；文件只用于类型识别 | 规则＋原生 |
| CAT-4 | 两份同名／同 bundle ID 应用，规范路径相同的别名，扫描范围外的候选和手动应用 | 同一规范包位置去重，不同副本保留名称／版本／完整路径；候选范围独立于扫描范围；不可用手动位置保留配置并标记 | 规则＋原生 |
| QUERY-1 | 查询 PDF、JPEG、http、https、mailto 和当前可解析的其他常用项 | 展示系统实际默认路径和候选；声明支持、默认、候选各有来源；http／https 是独立关联 | 原生只读＋界面 |
| QUERY-2 | 查询成功无默认、候选为空、输入未解析、查询失败及目录局部失败 | 五种情况不互相冒充；查询失败保留最后有效观察并标明待更新，提供重查 | 规则＋界面 |
| UI-1 | 应用名／版本／路径／声明搜索及右侧筛选；无结果／无声明；同名副本与长路径 | 按[桌面决议](../issues/09-desktop-workflow-details.md)的搜索范围显示结果，空态无无关旧详情；完整路径可查看，保留类型／协议入口 | 界面 |
| UI-2 | 最小内容区域 1000×700，实机规模与压力样本，长等待条出现 | 双列表独立滚动；搜索、应用信息与请求状态可见；无横向溢出，全部动作可到达；内容区域与原生标题栏分别核对 | 界面＋原生 |
| UI-3 | Tab／Shift-Tab、↑↓／Home／End、Enter、Escape、⌘F、⌘1/2/3 | 遵循[焦点决议](../issues/09-desktop-workflow-details.md)，只移动当前列表，不误写入、不抢输入法按键；关闭顶层对话框后返回合理触发点 | 界面＋原生 |
| UI-4 | 切换入口、外部默认变化后刷新、原应用消失 | 按身份保留会话搜索和选择；刷新采用新默认，待决目标不丢失；原副本消失不自动替成同名应用 | 规则＋界面 |
| WRITE-1 | 在应用行或候选详情中明确修改一个关联 | 提交的是具体副本；不产生暂存／批量；受理返回快照，界面分别显示提交、系统返回和回读，不能提前变为成功 | 规则＋界面＋原生 |
| WRITE-2 | 用户查看后默认已外部改变、目标卸载、目标已经是当前具体副本 | 提交前重新查询；外部变化先返回新观察让用户再次明确选择；不可用目标不发 setter，目标已是当前副本则无需写入 | 规则＋界面 |
| WRITE-3 | 连点、丢失提交应答、重复客户端请求标识、同标识不同参数、另一个关联并发提交 | 同请求只产生一次 setter；冲突明确返回；待决或回读未确定时阻止所有新写入，查询与浏览可用 | 规则＋界面 |
| WRITE-4 | completion 成功后实际为目标、另一同 bundle ID 副本、旧默认或其他应用 | 只有成功＋规范路径一致确认本次修改；其他情况分别保留目标及实际路径，不用 bundle ID 抹掉差异，不自动重试 setter | 规则＋原生 |
| WRITE-5 | completion 返回原生错误；或成功后回读失败 | 保存实际 NSError 字段与独立回读；不伪造取消分类、没改动或回滚；回读失败保留旧观察及写入门控，成功重查后再判定 | 规则＋界面；真实错误另见下方观察门槛 |
| WRITE-6 | 长时间待决、极晚 completion、调用者取消等待、页面重载、取消订阅 | Go 请求生命周期继续；不按超时宣布失败／撤回；实际回调可安全落地，结果仍绑定原关联；前端可用快照恢复 | 规则＋原生 |
| SYNC-1 | 事件先到／快照先到、旧查询晚回、重复事件、前端失去提交应答 | 单调版本和请求身份维持新状态，旧结果不覆盖新观察；重订阅与快照能恢复，不以重新发 setter 解决同步 | 规则＋界面 |
| STORE-1 | 手动项保存后重开；文件损坏；原子保存失败 | 手动项按版本恢复；损坏文件保留并报告，不覆盖为空；写入失败不伪装成功 | 规则＋原生 |
| STORE-2 | 记录保存前失败、保存后提交前崩溃、提交后强制结束 | 保存失败时 setter 次数为 0；其余情况重开显示可能提交／旧结果未知并查询，从不自动重放 | 规则＋原生 |
| STORE-3 | completion 与回读已确定，但清除未定记录失败 | 已知系统结果与存储问题分别展示；再次启动仍谨慎处理遗留记录，不把存储错误写成系统失败 | 规则＋界面 |
| RECOVER-1 | 重开后当前默认等于或不等于旧目标；再手动修改 | 旧请求仍未知；当前查询有独立结果；有效查询后先显示旧请求可能完成的说明，明确提交才建立新请求并替换单条记录 | 规则＋原生 |
| RECOVER-2 | 新进程已提交新请求，旧请求随后可能影响当前默认 | 不承诺跨进程全局串行或旧请求撤回；后续查询如实展示变化，新请求的结果不补写旧 callback | 规则＋界面 |
| QUIT-1 | 菜单退出、⌘Q、最后窗口关闭，且有未定请求；重复触发、提示时回调到达 | 统一提示，可留在应用或仍退出；不阻塞主线程，不重复提示或崩溃；退出不宣称撤回；受理前记录已存在 | 规则＋原生 |
| BUILD-1 | 使用锁定依赖构建普通／开发 `.app` 并启动 | 按[架构方案](architecture-proposal.md)固定 Go／Wails 与 npm ci；macOS 下限一致为 13；稳定产品身份、ad-hoc 签名；在已选自用环境能运行 | 构建＋原生 |
| BUILD-2 | 生产构建与启动 | 展示正式应用功能；不包含问候示例、演练控制栏、压力数据或本轮原生探针；正式 UI 不依赖原型开发参数 | 构建＋界面 |

Go 规则测试应验证边界可观察行为，避免镜像实现细节；界面使用少量端到端核心路径和键盘人工核对。以本机 92 份应用的历史抽样作为规模依据，追加长名称、重复副本、无声明及 1000 级关联条目作压力场景，数字是测试夹具，不是产品目录上限。原生系统处理没有固定完成时限；记录扫描耗时、等待期响应和测试设备，不能把时间限制用成 setter 的成功／失败判断。

## 必测实机流程

在产品实现之后，用正式 Wails 壳与服务完成：

1. **只读浏览**：扫描当前目录，查 PDF、图片及 http／https／mailto；对照适配器读回的具体路径。试用真实应用／文件选择器、手动项跨启动保存、1000×700 的焦点和滚动。
2. **专用关联写入**：独立测试类型和协议各从 A 改为 B，经过真实 completion 和回读；再明确改回可用的 A 副本并记录实际路径。这是新修改，不使用“恢复按钮”。副本差异或系统拒绝本身不要求平台必须接受目标，但至少一项专用类型和一项专用协议须取得真实成功路径，以证明两类接口接入有效。
3. **生命周期与恢复**：在真实 Wails 壳内用可控适配器覆盖待决时三类退出入口、提示留在／退出、重新打开旧记录、快照同步和晚到结果；运行强制结束后的未定记录恢复。替身运行明确标记，不冒充系统待决退出观察。
4. **真实特殊行为观察**：在专用关联上尝试原生取消／拒绝、实际系统请求待决时退出并重开、同 ID 多副本和未声明应用。系统提示由用户操作；同时记录人工选择、原生结果与回读，不能用自动日志猜测用户按了什么。
5. **收尾核对**：记录测试前后日常默认快照；只注销此次专用测试应用，不重置 Launch Services 全库。回读仍指向 fixture 时记录残留与具体路径；清理不成功需处理后再签收，不声称“恢复为从未设置”。

常用 PDF、浏览器、邮件关联本轮验收方案默认只读。日常默认的真实改写与改回可另行做具体范围实验；采用本规格或通过专用关联不代表已授权所有日常默认写入，也不等于保证每个系统协议接受任意目标应用。

## 特殊观察的完成门槛（已选分层验收）

**采用分层验收并保留实机限制。** 上表确定性行为、构建和必测实机流程 1–3、5 必须通过。流程 4 必须有针对性的尝试与记录；如果当前系统没有提供取消／拒绝或持续待决的可触发机会，标记“尚未观察”，保留替身的完整边界验证与用户可见结果未知语义，不将其算作原生通过，也不因此无限期阻塞自用首版。实际出现崩溃、重复 setter、错误成功、丢失记录或无法重查等缺陷不得以“未观察”豁免。完整特殊行为实证不足时，成品报告必须列明覆盖限制。

未采用将全部特殊实证列为成品完成前提的比较方案。系统机会不足时的「尚未观察」只适用于上面明确列出的特殊情景，不能替代专用类型／协议真实成功或必测的正式窗口生命周期验证。

本选择决定成品如何签收，不重开已经确认的持续等待、手动改回、逐项写入、单条未定记录或当前系统兼容范围。

## 成品记录格式

每轮记录日期、系统／架构、产品构建身份及工具版本，关联身份、目标完整路径、提交前默认、用户明确动作、系统提示是否出现及实际按钮选择、completion domain／code／description、各次回读路径与阶段、退出方式／重开查询、清理结果。按行填写「通过」「失败」「尚未执行」「尚未观察」，注明原生／替身／界面，附日志或截图。日志中的等待时长只是观察，空错误不证明用户取消；回读匹配不反推旧进程请求成功。

签收时逐项给出证据和未观察限制。任何核心失败都保持未完成；“没有出现提示”只能用于允许的特殊观察条目。先前探针可以解释设计依据，不能直接填成正式产品测试通过。
