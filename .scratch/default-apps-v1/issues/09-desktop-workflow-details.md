## Question

前置决策：[首版的关联目录与候选应用应如何定义？](03-association-catalog.md)、[应用视角与关联项视角如何组成首版主界面？](04-main-workflow-prototype.md)、[修改默认关联时，用户如何确认结果与处理失败？](05-change-semantics-prototype.md)

在用户已选择的 A「应用优先」桌面结构中，用可操作的抛弃式原型决定足以进入首版开发的交互细节：应用与关联长列表如何搜索和滚动，最小窗口如何保证内容和操作可达，以及空态、键盘焦点和修改后的刷新如何表现？

先只读抽样已安装应用的声明质量和目录规模，以真实规模补充原型数据；记录哪些数字是实机观察、哪些是压力样本。比较应用列表与详情区滚动方式，明确搜索应用名、版本、位置和声明关联时的结果含义；无匹配或应用无声明时不显示无关旧详情，并保留从文件类型/协议继续查找的入口。

走通同名副本、同扩展名的不同类型、较长名称与路径、已选应用消失，以及切换浏览方式后的选中项和待修改状态。根据修改语义决策确定刷新后如何呈现外部变化；不承诺原生接口无法保证的恢复行为。

与用户确认最小桌面窗口、Tab/方向键的导航与焦点规则、Escape 关闭对话框以及搜索快捷键的取舍。原型方案切换用的浮动底栏和左右箭头不是产品导航要求。仅针对 macOS 桌面窗口，不加入移动端或平板布局，不连接真实默认设置写入。

资产和用户结论记录在本工单；验收工单引用这里的决定，不复制未验证的行为承诺。

## Answer

首版在已选定的「应用优先」结构中采用 **A 双列表独立滚动**。左侧应用列表与右侧关联列表分别滚动；顶部浏览入口、所选应用信息、搜索／筛选和全局修改请求状态保持可见。关联项详情通过可关闭的对话框展开；B、C 滚动方案仅作历史比较。

### 窗口与内容可达性

最小 **内容区域为 1000×700**，按桌面界面逻辑像素理解，原生标题栏高度另计。正式实现需核对 Wails 窗口参数对应的实际内容区域。只针对 macOS 桌面；不增加移动端布局。长列表、长名称和路径依靠各区域滚动、折行及详情完整展示；不要求逐项 Tab 穿过整个目录。原型的 960×640 是比较下限，不是首版验收尺寸。

### 搜索与选择

- 应用搜索覆盖名称、版本、安装路径及声明关联；bundle 元数据也可匹配。命中应用信息时展示该副本全部声明，只有声明命中时展示匹配声明，并说明匹配范围。右侧独立筛选进一步缩小当前关联列表，常用关联优先。
- 文件类型／URL 协议入口各自保存本次会话中的搜索、选中关联和列表滚动位置。切换应用从该应用的首个可见关联开始；切换入口或刷新不丢失已提交请求，不把视图选择当作修改草稿。
- 搜索无结果时清空无关旧关联详情；应用没有声明时显示明确空态，并保留文件类型和 URL 协议入口。查询失败、未解析、无默认和无声明分别表达，不能从空候选推导默认不存在。
- 同名应用按具体副本分别显示版本与路径；详情给出完整路径。同扩展名的不同类型分别展示类型身份和默认。原型的原始扩展名未归一化样本仅用于压力验证，正式解析继续遵循目录决议。
- 刷新发现所选应用副本消失时，从可用应用列表移除它，保留原路径的消失提示并清空其关联详情，不自动换成同名副本。已查询的默认若仍指向该路径，分别显示实际回读与目录缺失；已经提交的请求仍绑定原关联和原目标。

### 键盘与焦点

Tab／Shift-Tab 跨控件；应用列表只有当前项作为 Tab 停靠点，关联列表停靠当前行名称及可用动作。↑↓／Home／End 在当前列表移动并同步选择；搜索框 ↓ 进入结果，不抢占其他控件或输入法的方向键。Enter 从应用进入关联列表，从关联名称打开详情；没有关联时进入筛选／空态可用入口。

Escape 关闭顶层对话框并返回触发控件；若焦点在搜索框则只清空该搜索。它不撤回任何已提交请求。⌘F 聚焦当前入口主搜索，⌘1／⌘2／⌘3 切到应用／文件类型／URL 协议。原型底栏的左右箭头只用于比较方案，不是产品快捷键。正式 Wails 窗口需验证原生菜单、WebView 和 macOS 键盘设置下的焦点表现。

### 修改、刷新与跨启动说明

在任何入口共享同一关联的当前默认与修改状态。全局等待条显示原关联项、目标副本完整路径和请求阶段，并可回到请求项；等待期间浏览和查询可用，新的写入暂停。刷新只查询，保留筛选、选中项与已提交目标；查询到目标也不能独自证明系统待决请求结束。原型中刷新先切换模拟 PDF 默认仅为演练，不是产品行为。

跨启动保留的未定记录以旧请求结果未知呈现，当前查询即使匹配目标也不补记旧请求成功。再次手动修改前展示旧请求仍可能完成及其目标，用户明确提交后才建立新请求；返回或 Escape 不提交。生命周期、存储及结果确认细节以[修改语义](05-change-semantics-prototype.md)和[架构方案](../assets/architecture-proposal.md)为准。
