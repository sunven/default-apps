## Question

前置事实与决策：[macOS 默认关联有哪些可用接口与系统限制？](01-macos-association-api.md)、[首版的关联目录与候选应用应如何定义？](03-association-catalog.md)、[Wails 中的原生确认、晚到回调与回读如何实际表现？](08-native-behavior-probe.md)

用状态交互原型，与用户决定首版的修改语义：逐项立即修改还是先选择后应用，是否包含批量设置，以及系统确认、回读结果和部分失败如何呈现？

走通单项成功、取消系统确认、部分成功、回读仍为旧值和原应用已卸载等情景；若支持批量或恢复，明确每项结果、恢复边界和无法保证的行为。界面不得把调用已提交等同于默认应用已生效。原型只模拟状态，不更改真实系统默认设置。

## Comments

### 2026-11-05 · 原生探针已结束，修改语义可开始讨论

[原生探针结论](08-native-behavior-probe.md)已经提供实机证据：Go 等待取消后仍可能通过系统确认并修改成功；同一应用副本的回读路径可能不同于用户所选路径。状态原型须纳入这两个实际边界。

系统确认取消/拒绝的具体 NSError 和真实系统请求待决时退出效果仍未测得。原型可以模拟这些情景，但不能宣称错误码或撤回能力已经验证；应分别呈现请求等待、等待已取消但结果未定、系统结果与回读实际路径。是否采用批量、恢复或退出提示仍由本工单与用户讨论，尚未定案。

### 2026-11-05 · 单文件状态原型已完成，等待修改方式与首版范围选择

资产：[可直接打开的修改交互原型](../../../frontend/src/prototypes/default-apps/change-semantics-prototype.html)、[运行说明与证据边界](../../../frontend/src/prototypes/default-apps/change-semantics-README.md)、[桌面视觉检查](../../../.taste-skill/change-semantics-inspect/report.json)。不连接真实系统，仅使用内存数据；沿用已选择的 A「应用优先」布局。

九个引导情景与自由操作均已在命名浏览器会话中验证。提交、回调与回读分开；晚到成功、同 bundle ID 副本差异、模拟拒绝、批量部分成功、旧值回读、恢复失败、原副本卸载和待决退出均可体验。退出后只标记当前查询与目标是否一致，旧回调仍未知，不把查询结果算成上次请求成功。桌面 1440、1280、1000px 检查均 0 FAIL / 0 WARN，1000×700 滚动操作与横向溢出检查通过。

待选方案：

- **修改方式**：逐项立即提交；或先暂存多个选择，再依次应用。建议首版逐项立即提交，符合应用优先界面的行内操作，也减少批量确认与部分失败的操作负担。
- **恢复范围**：首版仅查看当前默认并手动改选；或提供本次会话的逐项恢复入口。建议首版手动改选；恢复不能撤销系统请求，且原应用副本可能已卸载。
- **长等待**：建议保持行内等待状态、继续浏览和查询，待决时禁止重复写入，退出前提示结果未定。原型也展示可选的「停止等待」入口，但它不能撤回请求。一次一项的调度与批量失败后继续仍为演示前提，未据此锁定产品规则。

本工单继续保持 `claimed`，没有用户 verdict，暂不记录 Answer 或关闭。以上是推荐及可审阅方案，不代表用户已选择暂存、批量、恢复或退出交互。

### 2026-11-05 · 用户选择逐项立即修改，记录决议

用户在原型完成后分别选择「逐项立即修改」「先不提供，查看当前默认并手动改选」「持续显示等待状态」。第三项问题已明确共同条件：两种等待方案均允许继续浏览和查询，暂停新写入，退出前提示结果未知。本工单据此关闭；暂存、批量、恢复与停止等待的原型情景留作回看。

## Answer

首版采用 **逐项立即修改**：用户从关联项行或候选选择中明确提交一项默认应用修改，不建立待应用草稿，不提供统一应用或批量设置。HTTP 与 HTTPS 分别查看、分别修改。用户已选择的 A「应用优先」主入口保持不变；文件类型和 URL 协议入口共享同一关联项的状态。

### 提交与结果

- 用户确认目标是一个具体的应用副本，包含路径。界面从提交起显示该关联项及所选目标，保留上次查询到的默认应用，不能点击后立即标记生效。
- 分别呈现「等待系统」「系统已返回，待回读」「回读结果」。完成回调不等于所选副本成为默认；收到结果后查询系统实际默认。
- 原生调用成功且回读路径与目标一致，才显示本次修改已确认。回读指向具有相同 bundle ID 的另一副本，仍显示实际名称、路径及与所选副本的差异；不静默合并成所选安装已生效。
- 回读仍是旧值或其他应用时，保留目标和实际默认，显示差异并提供重新查询、手动再次选择。不能按预设秒数变成成功，也不能自动反复写入。
- 系统返回错误时，显示真实原生错误及实际回读，不能保证操作没有影响默认，也不把错误等同于已恢复。错误域、代码、描述由实际接口保留；系统取消或拒绝的专有错误码尚未验证，不使用原型虚构代码作分类依据。
- 回读失败时保留最后一次有效查询并标明待更新，允许再次查询；没有有效回读之前不把本次修改宣称成功。查询失败后的具体服务返回与刷新机制由架构工单确定。

### 长等待与并发写入

首版**持续显示等待状态**，不提供「停止等待」或「撤回请求」按钮。等待期间继续浏览、搜索、切换应用或关联项，以及查询当前默认；系统请求待决或完成后的回读尚未确定时，暂停新的写入，避免重复提交及同时堆叠确认。

查询到某个当前默认只代表该查询时刻的事实，不能据此推断待决系统请求已经结束。晚到回调仍须安全接收并回读，状态绑定到原关联项，不随着用户切换视图丢失。界面等待时间长也不能自动标记原生失败或宣称撤销；不承诺所有 macOS 上有固定线程、延迟或确认提示。

### 改回与退出

首版**不提供恢复修改前应用的按钮**。用户查看当前默认后手动选择想用的现有应用，作为一项新修改提交，继续经过系统结果与回读。若原来的应用副本已经卸载，不保证还能改回，也不自动替换成另一份同名安装。没有批量恢复、原子回滚或系统撤销承诺。

存在已提交但结果未定的请求时，用户退出前看到提示：系统可能在应用退出后完成修改，重新打开需查询实际默认。提供「留在应用」与「仍然退出」；退出不宣称撤回请求或恢复旧默认。重新打开不自动重放写入，先查询现状；即使当前默认等于曾选目标，也不能证明退出期间旧请求的完整结果。跨启动是否保留目标或请求记录交给架构工单，不由内存演示推定。

### 依据、资产与后续

[原生探针结论](08-native-behavior-probe.md)证实取消等待后仍可通过系统确认成功，以及同 bundle ID 应用副本的回读路径差异。系统拒绝错误与真实待决请求退出结果仍未实测；成品验收应区分通用状态处理与有实机证据的行为。
