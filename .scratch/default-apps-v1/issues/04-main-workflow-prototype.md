## Answer

首版采用 **A「应用优先」**。此选择来自用户对三个桌面原型的反馈；此前推荐的 B 不作为首版主入口。

- 默认进入应用视角：左侧是已发现应用和搜索，右侧显示所选应用的名称、版本、安装位置及声明支持的关联项。同名安装副本分别展示。
- 每个声明支持的关联项同时显示系统当前默认应用；声明支持与当前默认分别表达。用户可以从该行选择所查看的应用，也可以打开关联项详情选择其他候选。
- 保留顶部「应用」「文件类型」「URL 协议」浏览入口。用户知道 PDF、扩展名或协议时，可以直接切到关联项视角，查看当前默认、系统候选和「选择其他应用…」。手动添加及文件识别回退沿用已确定的目录决策。
- A 适合先找到某个已安装应用、再检查它支持哪些内容以及哪些内容当前交给其他应用的工作方式。文件类型与协议入口承接从内容出发的查找，不要求用户先知道当前默认应用。
- 只考虑 macOS 桌面窗口。现有 A 原型作为主布局依据，B、C 留作比较资产；产品页面在规格完成后另行实现。`npm run prototype` 和无 `variant` 参数的原型入口已经默认打开 A。

资产：[A 应用优先原型](http://127.0.0.1:9245/?prototype=default-apps&variant=A)、[A 对比图](../assets/prototype-A.png)、[源码和运行说明](../../../frontend/src/prototypes/default-apps/README.md)、[视觉评议](../assets/prototype-critique.md)。此前记录的浏览器与桌面尺寸检查仍适用于该原型；本轮只记录选择，没有重新进行浏览器验证。

这项决议只确定主入口和导航结构。原型的待修改状态、统一应用按钮不代表用户已经选择批量写入语义；真实修改、系统确认、取消和回读结果仍由[修改默认关联时，用户如何确认结果与处理失败？](05-change-semantics-prototype.md)决定。最小窗口、真实目录规模下的搜索、滚动、空态和键盘行为交由[应用优先界面如何处理长列表、搜索、空态与键盘操作？](09-desktop-workflow-details.md)进一步确定。
