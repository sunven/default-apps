## Question

前置事实与决策：[Wails V3 如何承载 macOS 默认关联能力？](02-wails-v3-native-bridge.md)、[首版的关联目录与候选应用应如何定义？](03-association-catalog.md)

在受控的本机测试环境中，用最小、抛弃式 Wails 原生调用探针取得修改语义和桥接决策仍缺的实机证据：系统确认期间窗口是否保持响应，completion 所在线程、完成到默认值读回可见的时机、取消 Go 等待后的晚到 callback，以及退出对未完成操作的影响。

根据已确定的候选应用策略，验证有声明的候选与手动选择应用的成功/拒绝边界，以及同一应用多份安装时 setter 与回读是否保留用户选定副本的语义；仅测试首版实际需要的情景。测试前明确关联项、应用副本、当前值与恢复方式，优先使用专门测试关联和隔离环境；涉及用户真实默认设置的实验须先得到该具体实验的授权。需要原生用户确认的步骤由用户操作，不代替用户同意。

这项任务用于取得决策依据，不交付产品服务。将探针作为独立资产链接，记录观察、未覆盖情景和恢复结果；任务完成后关闭工单，修改语义与架构仍分别由其决策工单决定。

## Comments

### 2026-11-05 · 实验与人工观察

在当前 macOS / arm64 自用环境准备了独立 Wails 3.1.0 探针和四个专用测试应用。用户在获知专用关联测试范围后多次要求继续；实际修改限定于新建的测试文件类型 `org.defaultapps.probe.7a9a0204.document` 和协议 `defaultapps-probe-7a9a0204`，没有执行 PDF、mailto、http 或 https 的 setter。

用户确认第一组实验「出现过，我选择了允许」，并确认取消 Go 等待的后续实验「已在当前提示中选择允许」。系统原生同意由用户操作。

最后一次原计划获取系统取消结果的请求，日志仍返回 `error: null`，并读回 A 的另一副本；用户没有反馈这一次的原生按钮选择，不能将它解释为系统取消已验证。该请求完成后关闭探针，注销本次测试应用并完成清理查询。

### 未覆盖情景与后续采用边界

- **系统确认取消/拒绝的具体 NSError 未取得。** 已知真实请求均成功；原计划取消的最后请求也返回无错误。后续状态原型可模拟取消/拒绝，但不能把样本当实机错误码。原生错误保留 domain/code/description，只有获得可靠依据时才映射成「用户取消」，否则显示具体系统结果并回读实际默认值；由[修改默认关联时，用户如何确认结果与处理失败？](05-change-semantics-prototype.md)决定具体呈现，并在[哪些验收情景足以让首版规格进入开发？](07-spec-acceptance.md)安排成品本机验收。
- **真实系统请求待决时退出后的系统结果未测试。** 人为回调实验只能证明本进程回调不再到达，不能承诺退出会撤回系统修改。修改语义应按「结果未知，重新启动后查询」设计；是否阻止退出或展示待决提示仍需用户决策。原生产品完成后再按确定的退出策略做受控验收。
- 未执行真实 PDF 切换、默认浏览器或邮件应用修改，未测试 Intel 或旧 macOS。可选 PDF 启动与恢复工具仅为后续具体授权实验准备，没有产生 PDF 实验基线文件。
- 本轮没有设置批量原子性、自动回滚或强制默认应用的产品承诺。技术边界已足够让后续决策采用异步请求、独立生命周期、每项回读和真实路径展示；保留验证空白，比猜测固定错误码或取消能力更准确。
