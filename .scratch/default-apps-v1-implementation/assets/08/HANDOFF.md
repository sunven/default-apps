# 08 lifecycle handoff

`internal/change.Service` remains the single request owner, state mutex, store and gate. The new source files are `quit.go`, `recovery.go`; admission/load and callback guards remain in `service.go`. Generated bindings are committed.

- `Snapshot.Recovery *Recovery {record: PendingRecord, ready: bool}` is an old process's record, never a current active callback. The corresponding session request remains `phase=recovered`, unknown completion and unconfirmed. `ActiveRequestID` is empty on recovery. `observeRecoveryLocked(QueryResult)` runs only for a fresh accepted observation of that association. Valid means known / no error / not stale; failures gate new writes and retain independent last valid current observations through the query service.
- `Submission.RecoveryRequestID` acknowledges the old target warning. `Submit` requires current valid recovery facts plus the matching ID, then ordinary preflight and atomic save. Only acceptance replaces `Recovery`; dismissal, no-op, rejection and save failure retain it. A final readiness check before saving handles recovery-query failure while another association's preflight runs. Reusing an existing recovered request ID returns its unknown request or a parameter conflict and can never dispatch, including after a later explicit request replaced disk.
- `Snapshot.Quit QuitState {promptID, prompt, exiting}` and public `RequestQuit() bool` / `RespondQuit(promptID uint64, exit bool) Snapshot`. The hook performs only a short state lock, no storage load/save or system query. Repeated native routes share one prompt; stale replies do nothing. Completion never auto-dismisses an open prompt. Staying publishes the new state; deliberate exit closes admission before asynchronously invoking `Options.Quit` exactly once. `Exiting` stays true through both close and terminate hooks.
- `main.go`: `application.Options.ShouldQuit` and `window.RegisterHook(events.Common.WindowClosing, ...)` both call `RequestQuit`; the latter calls `event.Cancel` before Wails destroys the window. `Options.Quit` invokes public `app.Quit`. No first-save work is performed in shutdown.
- In `service.go`, `publish` drops queued publications once `Quit.Exiting`; `submitted`, `completed`, `finishReadback` return without new work. `Query` checks exiting before native work, after an in-flight result returns, and after record clearing before finalization. It returns `context.Canceled` instead of publishing late observations. `Submit` checks exit before reservation, before save and after save; exit during blocked save leaves the durable uncertainty without dispatch. Keep these exact guard locations when merging 07's query changes.
- 07 merge: preserve its `decisions` map, `decidedLocked(in)` before submission lookup, and `decideLocked(in,result)` in the fail closure. Keep the recovery acknowledgment in same-submission equality. A superseded query must never call `observeRecoveryLocked` or release recovery admission. Keep `state.quit?.exiting` in frontend submit and blocked checks; `submit` accepts fourth optional `recoveryRequestID=''` and stores it with the original input. `ChangeStatus` excludes recovered-only requests because `LifecycleStatus` owns the independent recovery notice. `App` adds `useRecoveryAction(changes)`, wraps `submitCopy`, and mounts `<LifecycleStatus>` plus the recovery dialog.
- 09 / 10 native adapter: callbacks must remain safe after exit and release only native-owned bookkeeping; do not retain/touch a window. The coordinator drops late results, never promises native cancellation. The dispatcher still receives `submitted` and copied `complete`; no setter is introduced here. Public native hooks must stay nonblocking even if native completion or disk work is slow.

The test-only `lifecycle_smoke` helper invokes installed NSMenu items / real menu key equivalents / NSWindow.performClose on the main thread; logs are buffered off the hook. The ordinary build contains no helper. `change_smoke` adds boot observation controls and counts `actualStarts` independently from Dispatch scheduling; reconcile 07's additional held-query fields without removing either. Native actual current-association writes are still entirely disabled in production.
