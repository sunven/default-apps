# Shared configuration boundary for ticket 06

`internal/config.Repository` exposes `Load(context.Context) (Document, error)` and `Update(context.Context, func(*Document) error) error`. Pass the same `*config.Store` instance to manual discovery/service and the change coordinator. `Update` holds a short storage mutex, reloads and validates the complete version-1 document, invokes the mutation, then writes/syncs a temporary file in the same directory and renames it. Other manual fields survive pending-record updates, and `Pending json.RawMessage` survives manual updates. No permanent history is stored.

The coordinator should marshal its one pending DTO into `Document.Pending` inside `Update`, before native dispatch. Load/decoding the pending DTO and request phase semantics belong to 06/08. `Pending` is intentionally opaque to the manual service. A clear should inspect request identity inside the update callback before clearing; a late clear for A must not erase replacement B. A failure before rename leaves prior bytes intact. A directory-sync failure after rename is reported as failure even though replacement may already be visible; callers must stay conservative and never submit a setter on any returned save error. Clear failure must remain separate from a known native/readback result. Callbacks must not recursively call the same store. Atomic writer injection (`NewStoreWithWriter`) is an agreed storage-boundary fault seam, not product configuration.

Ordinary `configuration.go` always uses `~/Library/Application Support/Default Apps/config.json`. Only a `manual_smoke` build accepts `DEFAULT_APPS_MANUAL_SMOKE_ROOT`, and it must be provided. The optional MCP and native picker driver are test-only. No setters or recovery lifecycle are implemented by 05.

The manual service (`internal/manual.Service`) returns `Saved` only after successful store update, leaves cancellation mutation-free, requires exact association choice for ambiguous input, and calls discovery's `StartScan` after commit. Discovery accepts an optional shared repository, merges selected manual identities and sources, and retains unavailable manual app paths. Application fields `Manual` and `Unavailable` describe these paths without replacing the application's canonical identity.

## Native evidence harness caution

The production frontend bundles `@wailsio/runtime`. Dynamically importing `/wails/runtime.js` in MCP JavaScript creates another runtime instance whose events module replaces `window._wails.dispatchWailsEvent`. The original React `Events.On` subscriptions then stop receiving native events even though the backend and the second runtime receive completed scans. This is a harness side effect, observed as versions 26–36 completing while the UI remained scanning, not a product scan failure. For lifecycle/recovery tests in 06–08 prefer real UI controls and DOM observations, or export a test-only hook from the existing bundled runtime. If bridge calls are necessary, preserve the pre-import dispatcher and restore it immediately after importing, before invoking the call; `check-native.py:service` does this. Use a fresh page/process to recover a dispatcher that was already replaced. Do not infer product event loss from a page whose runtime the harness replaced.

05 confirmed genuine native file and app picker success with human selections, then actual quit/relaunch. The fixture-specific metadata, original saved paths, same-ID copies, unavailable/reappearing state, and unchanged independent native defaults are recorded in `human-*.json`. No setter was added or invoked. The human's statement is corroborating context; panel URL, UI, config, and fresh queries are the acceptance evidence.
