# Ticket 06 lifecycle boundary

The implementation is `internal/change.Service`. `main.go` creates one `config.Store` from `changeEnvironment`, then shares it with change, manual, and discovery. All formal React browsing now calls `change.Query`; the association service is the common system-query cache and is still registered for earlier public boundaries.

Public generated binding surface:
- `Submit(context, Submission) SubmitResult`: requestID, canonical association, targetPath, and `Expected{known,path}` (empty path means a valid no-default observation). Typed outcomes are accepted, existing, conflict, busy, changed, no_change, invalid, target_unavailable, preflight_error, storage_error, unavailable, interrupted. Same semantic accepted ID returns a defensive copy; same-ID in-flight callers share the admission result rather than receiving an incomplete request.
- `GetSnapshot() Snapshot`: global monotonic version, busy/admission gate, active request ID, session requests, per-association `QueryResult`s, writable kinds, independent load error. Subscribe to `defaultapps:change` before this read; event and snapshot have the exact same Go type. Event delivery order can differ; consumers must compare global version.
- `Query(context, Association) (QueryResult,error)` and `Requery(context, Association) (Snapshot,error)`: query only. Queries issued while completion is still absent cannot settle that request. Query result versions fence observations per association. A known completion plus valid independent post-completion query resolves the current request; exact target path and nil native error alone produce `confirmed`.

`Dispatcher.Dispatch(association,target,submitted,complete)` is the native boundary. Run initiation asynchronously on public Wails main-thread APIs in 09/10. Call `submitted` only when the native call actually runs. It does no disk I/O. `complete(*NativeError)` immediately copies domain/code/description; callback can be inline or on any thread. The service owns the lifetime after admission, uses no caller context for dispatch/readback/clear, has no product timeout, and ignores duplicate/late callbacks. Native operation ID and C ownership remain the native adapter's responsibility in 09/10.

`PendingRecord` is JSON inside `config.Document.Pending`, saved atomically before any dispatch. It contains request ID, association, canonical target copy, preflight default, phase and timestamps. The durable phase is deliberately `accepted`, with acceptedAt and empty submittedAt: a crash cannot prove whether dispatch happened. In-memory state has submittedAt/completion/readback separately. No second disk write runs on the native initiation thread. Pending clear checks the stored request ID, preserves current manual fields, and releases only the matching active request gate. A clear error is attached separately to the resolved request and permits a later explicit request to replace the leftover record.

First access loads disk once (`sync.Once`) before any admission. Existing records currently become conservative `phase=recovered`, readback unknown, and block writes. This is a deliberately unfinished recovery UI boundary for 08, not a restored current-process callback. 08 must replace this temporary recovered gate with its explicit current-observation/warning/replacement flow and shared native quit logic. Do not call `Recover` from the frontend: no such mutating public method is exposed.

07 still owns foreground refresh/coalescing, full obsolete-query schedules, reload/transport-reply recovery, and disappearing-copy lifecycle. Current React `useChanges` subscribes before fetching snapshot and ignores versions <= current. It keeps a client ID when a binding rejects and offers a query-only original-request lookup. `recoverReply` retains uncertainty when a snapshot lacks the ID, so one empty snapshot cannot reopen admission. 07 still needs to persist the original ID/parameters across reload and reconcile an in-flight or definitely rejected admission instead of leaving that case waiting indefinitely. The basic backend accepted lifetime, duplicate ID, and defensive-copy rules are verified here. 08 should share the same state and mutex for quit admission closure; do not build a second request owner.

Production `change_environment.go` returns no writable kinds and a disabled dispatcher. Only `change_smoke` supplies a controlled adapter and isolated root. Neither current build contains a native setter. The tagged smoke control server binds loopback on an ephemeral port written to the isolated root; it is not a Wails product service or UI control. `manual_smoke` is included only to reuse the existing public-WebKit screenshot helper. Omit change_smoke/manual_smoke/mcp from deliverable builds.
