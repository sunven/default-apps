# 08: 待决退出与重启恢复

**What to build:** 存在未定修改时，用户退出前可选择留下或仍然退出；再次打开后能查看旧请求与当前默认，理解旧请求仍可能完成，并通过新的明确动作继续修改。

**Blocked by:** [06: 单项修改的完整请求流程](06-single-change-lifecycle.md).

**Status:** ready-for-agent

- [ ] 正式 Wails 窗口的菜单退出、⌘Q 和最后窗口关闭使用公开 ShouldQuit／WindowClosing 接入同一 Go 判断；待决或回读未确定时只显示一个退出提示，hook 立即返回，不阻塞主线程等待用户或 setter。（QUIT-1）
- [ ] 提示说明系统可能在退出后完成修改，提供“留在应用”和“仍然退出”。留下后可继续查询；确认退出采用一次性放行，防止循环提示，退出开始后不受理新写入。（QUIT-1）
- [ ] 重复退出、提示期间 completion 到达、提示关闭和实际关闭之间的竞争均保持一致状态；后续回调不触碰已销毁界面，资源清理有界，不声称退出撤回了系统请求。（QUIT-1、WRITE-6）
- [ ] 未定记录沿用 06 的提交前保存，正常退出与强制结束均不依赖退出时或 app.Run 返回后才首次落盘；保存后尚未提交就崩溃，也以“可能提交／旧结果未知”恢复。（STORE-2）
- [ ] 重启读取单条旧记录并查询当前默认，不恢复旧 callback、不重放 setter、不无限等待旧进程回调。当前默认等于或不等于旧目标都保持旧请求结果未知，当前观察独立呈现。（RECOVER-1）
- [ ] 旧记录恢复后，当前查询失败时保留重查并阻止新修改；获得有效观察后，用户再次修改前看到旧请求可能仍会完成及其目标的说明。返回或 Escape 不提交，明确提交后才创建新请求并原子替换旧记录。（RECOVER-1）
- [ ] 新请求继续遵守一次一项、提交前检查与先保存再提交规则；明确说明串行门控只覆盖当前进程。旧请求后来影响默认时，查询如实反映变化，不补写旧 callback，也不承诺旧请求已撤回。（RECOVER-2）
- [ ] 已知结果后的记录清除失败，会在本次会话分别显示存储问题；重启后遗留记录仍按旧结果未知处理，不根据匹配回读反推成功。（STORE-3）
- [ ] 在正式 Wails 壳中用可控适配器验证三种退出入口的留下／退出、重复触发、提示时 completion、保存后提交前结束、提交后强制结束、重开查询与再次明确修改；记录磁盘状态与 setter 次数，证明重启不会自动提交。（STORE-2、RECOVER-1、QUIT-1）
- [ ] 以受控外部变化验证旧请求可能影响新进程时的呈现；新增提示符合已确认的对话框与焦点规则。替身运行明确标注，真实系统待决退出的尝试和限制由 11 记录，不以本项替身结果冒充实证。
