# 05: 手动补充并跨启动保存

**What to build:** 用户可以补充扩展名、协议和其他位置的应用，用真实文件识别未知类型，并在重新打开应用后继续使用这些手动项；保存或读取失败会明确呈现。

**Blocked by:** [03: 从已安装应用浏览关联](03-app-first-discovery.md).

**Status:** resolved

- [x] 手动扩展名与协议经过正式解析和规范化，再按身份合并种子、声明与手动来源；多类型歧义供用户明确选择，不任意采用第一个类型。（CAT-2、CAT-3）
- [x] 未知扩展名可通过原生文件选择器识别类型；只识别整类类型，不读取文件内容或改变该单个文件的默认。仍未解析时解释原因并禁写，取消选择不添加或提交。（CAT-3）
- [x] 通过原生应用选择器添加目录外应用位置，并提供关联项的“选择其他应用…”入口；选中具体副本本身不修改默认，不因未声明支持而承诺或否定系统能否接受。（CAT-4）
- [x] 同规范包位置合并，其他同名／同 bundle ID 副本保持独立；手动位置不可用时保留配置、路径和不可用提示，允许重新选择，不悄悄替成另一副本。（CAT-4）
- [x] 手动关联与应用位置保存在用户 Application Support 下的版本化原子 JSON，重开后恢复并重新查询当前默认；目录、图标及默认观察可重建，不写成永久操作历史。（STORE-1）
- [x] 配置读取损坏或版本无法安全处理时保留原文件并报告，不能覆盖为空后声称恢复；保存失败不显示已保存。保持既有配置数据，不让一次更新丢失其他手动项。（STORE-1）
- [x] 提供可替换存储边界，供后续 06 使用同一原子保存机制写入单条未定记录；本项的独立交付是手动项跨启动保存，无需提前实现修改请求。
- [x] 在正式窗口操作真实文件／应用选择器，验证成功、取消、未知、歧义及目录外应用；跨启动核对手动项。用确定性故障验证损坏文件保留、原子保存失败、规范路径去重和不可用位置恢复。（CAT-3、CAT-4、STORE-1）

依据：[实施入口](../spec.md)、[目录与候选决议](../../default-apps-v1/issues/03-association-catalog.md#answer)、[架构方案](../../default-apps-v1/assets/architecture-proposal.md)、[验收矩阵](../../default-apps-v1/assets/acceptance-criteria.md#验收矩阵)。

## Answer

已实现正式手动关联／应用服务、版本化原子 JSON、按明确身份恢复的目录以及真实原生文件／应用选择器。扩展名歧义必须明确选择；动态未知类型禁写；取消无写入；应用按规范包位置去重，同 ID 不同位置保持独立。损坏或不支持的配置保留并报告，保存错误不发布成功。

确定性 Go race 与 React 交互检查、正式 Wails 窗口中的成功／取消／未知／歧义、应用副本／跨启动／失效恢复均已完成。证据与复现脚本见 [05 验收记录](../assets/05/README.md)。此交付没有调用默认应用 setter。06 可使用同一 `config.Repository` 原子边界保存单条未定记录，具体约束见 [HANDOFF.md](../assets/05/HANDOFF.md)。04 主布局合并时保留其布局并接入此处的手动入口；组合检查单列于集成记录。
