# 09: 真实文件类型修改

**What to build:** 用户在正式应用中明确选择文件类型及具体应用副本后，可向 macOS 提交真实修改，持续查看系统处理与回读结果；专用测试类型证明这条完整路径能实际生效。

**Blocked by:** [07: 刷新、重载与晚到结果同步](07-refresh-reload-synchronisation.md), [08: 待决退出与重启恢复](08-quit-and-recovery.md).

**Status:** ready-for-agent

- [ ] 在已有目录、修改协调器、持久化和退出流程内接通公共文件类型 setter；所有生产写入经过同一 Go 受理路径，不绕开去重、预检查、未定记录或门控。07、08 的确定性验证通过后才启用真实文件类型写入。（WRITE-1、WRITE-2、WRITE-3、STORE-2）
- [ ] 使用公开 Wails 主线程调度，仅在主线程发起短小原生调用，等待系统期间界面可用；复用现有 AppKit run loop，不修改 Wails 内部实现或另建主循环。（WRITE-6）
- [ ] 原生边界仅传可拥有的数据和数值请求标识，明确输入、对象、block、返回数据及 callback 登记的释放责任；不跨边界持有普通 Go 指针，不因调用者停止等待提前释放仍可能被使用的句柄。（WRITE-6）
- [ ] completion 可来自任意线程，立即复制 NSError 字段并交 Go 更新状态与独立回读；不在 callback 中等待界面，不根据历史探针推定固定线程或完成时限。（WRITE-5、WRITE-6）
- [ ] 从正式关联行或候选详情提交具体副本，只有原生成功且回读规范路径一致才确认；另一个同 bundle ID 副本、旧默认、其他应用与真实错误均保留目标、系统结果及实际路径，绝不自动重发。（WRITE-1、WRITE-4、WRITE-5）
- [ ] 用独立专用文件类型及可辨认的 A／B 应用副本，完成 A 到 B 的真实修改与回读，再明确选择可用 A 作为新请求改回；至少取得一项真实成功路径，保留完整日志和正式窗口证据。不能用历史探针结果代替本项验收。（WRITE-1、WRITE-4）
- [ ] 尝试同 bundle ID 多副本及手动未声明应用，按实际系统结果呈现，不能要求平台必须接受任意目标。系统错误出现时保留原始字段；未出现的错误或副本差异用受控适配器继续验证规则，证据区分原生与替身。（CAT-4、WRITE-4、WRITE-5）
- [ ] 验证原生请求等待期间可浏览、查询和重载，晚到结果仍安全归属；无法自然触发的长等待用边界验证补充并注明限制，不使用固定超时宣称取消或失败。（WRITE-6）
- [ ] 每次实验记录关联身份、目标完整路径、提交前默认、用户动作、系统提示与人工按钮选择、completion 和各次回读。日常 PDF、浏览器及邮件默认保持只读；保存前后基线并只清理此次专用夹具，记录并处理残留，不重置 Launch Services 全库。
