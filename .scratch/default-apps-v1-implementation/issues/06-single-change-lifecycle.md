# 06: 单项修改的完整请求流程

**What to build:** 用户明确选择具体应用副本后，界面立即跟踪这一项修改，分别呈现受理、系统返回和实际回读；等待期间仍可浏览与查询。通过正式界面、Go 服务和可控适配器完整验证这一流程，真实系统写入由 09、10 接入。

**Blocked by:** [05: 手动补充并跨启动保存](05-manual-items-persistence.md).

**Status:** claimed

- [ ] 应用关联行和候选详情均能明确提交单项修改，目标包含规范副本路径；三种浏览入口共享 Go 持有的请求与观察。无暂存、批量、恢复、停止等待或撤回按钮。（WRITE-1）
- [ ] 受理前检查关联可解析、目标应用可用及写入门控，重新查询默认。默认与用户查看时不同时返回新观察并要求再次明确选择；目标已是当前具体副本时返回无需修改；校验或查询失败不调用 setter。（WRITE-2）
- [ ] 明确提交生成客户端请求标识；相同标识与相同参数返回已有请求，同标识不同参数返回冲突。连点、重复提交和其他关联并发提交不会产生重复 setter；全局只允许一个活请求。（WRITE-3）
- [ ] 使用 05 的存储机制，在原生提交前原子保存单条未定记录，含请求标识、关联、目标副本、提交前默认、阶段和时间；保留手动配置。保存失败明确显示未提交，setter 调用次数为 0。（STORE-2）
- [ ] 受理返回请求快照，不等待系统确认；已受理与已实际提交可区分。系统 completion、回读和最后有效观察分别保存，事件与快照带身份和单调版本，为 07 的交错与重载处理提供依据。（WRITE-1、SYNC-1）
- [ ] 只有 completion 成功且回读规范路径匹配目标，才确认本次修改；另一同 bundle ID 副本、旧值和其他应用展示目标与实际差异。查询到目标不能单独结束仍待决的请求，也不能触发自动重发。（WRITE-4）
- [ ] completion 错误保留原生 domain、code、description，并独立回读；不推测取消、没有改动或回滚。回读失败保留最后有效观察及重查入口，在得到有效回读前继续阻止新写入；重查只调用查询。（WRITE-5）
- [ ] 已知系统结果与有效回读呈现后清除未定记录并结束该次门控；清除失败分别展示已知结果和存储问题，不改写成系统修改失败。正常清除和错误清除均保留手动配置。（STORE-3）
- [ ] 全局请求状态显示原关联、目标完整路径和阶段，可返回请求项；任一请求待决或回读未确定时禁用所有新写入，搜索、切换与查询仍可用。1000×700 下等待条、应用信息、搜索与列表动作可达，后续与 04 的完整浏览界面组合验收。（UI-2、WRITE-3）
- [ ] Go 请求生命周期独立于绑定调用等待和前端监听；不按时限宣布成功、失败或撤回。可控适配器能够延迟 completion、返回错误和不同回读，以正式服务状态驱动界面。（WRITE-6）
- [ ] 用 Go 规则与正式界面集成验证正常成功、全部提交前分支、同标识冲突、跨关联忙状态、副本不匹配、错误／回读失败、保存／清除失败，断言 setter 次数及磁盘记录；验证无需真正改变系统默认。
- [ ] 可控适配器通过测试环境注入，生产界面不含演练开关，也不把替身结果冒充系统事实；在 07、08 完成并由 09 接通之前，生产写入保持不可提交。（BUILD-2）
