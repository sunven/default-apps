# 07: 刷新、重载与晚到结果同步

**What to build:** 用户刷新、切换入口或重载前端后，仍能看到同一修改请求及最新有效观察；外部默认变化、应用消失、丢失应答与晚到结果不会造成重复修改或错误成功。

**Blocked by:** [06: 单项修改的完整请求流程](06-single-change-lifecycle.md).

**Status:** claimed

- [ ] 前端通过类型化事件与 Go 快照同步；订阅和初始快照不会遗漏极快完成。按关联／请求身份和单调版本处理事件先到、快照先到、重复事件及旧查询晚回，新状态不被旧结果覆盖。（SYNC-1）
- [ ] 丢失提交应答时按原请求标识查询或复用同一标识恢复状态；前端重载或重新订阅后仍能恢复活请求及必要的最后结果，不生成新标识重新调用 setter。（WRITE-3、SYNC-1）
- [ ] 调用者取消等待、取消订阅、切换视图或页面重载不终止 Go 请求；任意晚到 completion 仍归属于原关联和目标，持续等待不按超时改判失败。（WRITE-6）
- [ ] 启动扫描目录，进入关联、用户刷新及应用回到前台时重查当前所见关联；completion 后回读原关联。目录与默认分别刷新，避免全库定时轮询或自动重试 setter。（UI-4）
- [ ] 后台扫描期间旧目录可浏览并标明更新情况，合并新结果后按身份保留会话搜索、选择和滚动状态。查询失败保留最后有效观察和错误，过期查询结果不能覆盖新观察。（QUERY-2、UI-4）
- [ ] 所选应用副本消失时移出可用列表，保留其原路径的消失提示并清空声明详情，不自动换成同名副本；系统默认仍指向该位置时分别呈现实际观察与目录缺失。（UI-4）
- [ ] 任一入口的刷新不丢失待决目标，当前查询即使匹配目标也不结束待决；全局状态、关联行及详情保持一致，重查只更新观察。（WRITE-6、SYNC-1）
- [ ] 用可控适配器与正式前端排列事件／快照／查询时序，验证丢应答、重复事件、取消与受理竞争、重载、极晚 completion、外部变化和副本消失；断言界面最终状态及 setter 次数。04 完成时保留其会话与焦点行为，最终组合由 11 核对。
